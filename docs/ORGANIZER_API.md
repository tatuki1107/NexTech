# 主催者画面のAPI接続

devの主催者画面を仮データから実APIへ移行する変更です。DBスキーマ変更・追加パッケージはありません。

## 接続した機能

| 画面 | 接続内容 |
| --- | --- |
| 共通 | ログインセッション復元、所属主催者の全ページ取得、主催者切り替え、ログアウト。所属なしなら主催者プロフィールを作成 |
| ダッシュボード | 選択中の主催者のイベント件数・参加確定枠・本日開催・次回開催 |
| イベント管理 | 全ページ一覧、実IDの詳細、タイトルのみの下書き、編集、公開、公開停止、完了、開催中止 |
| フォーム | 日本時間、複数日開催、カテゴリ、タグ検索・選択、会場・住所・配信URL、定員、申込期間、待機受付、参加条件 |
| 申込管理 | 実申込の全ページ取得、状態別絞り込み、氏名・メール・UUID検索、表示名・日時ソート、詳細、絞り込み結果のCSV |
| 当日受付 | 日本時間の日付で開催イベントを選択、参加確定のみ受付、確認付きの受付取消、サーバー結果から人数再計算 |
| 分析 | 主催者自身の期間集計、月別・カテゴリ別、参加率・取消率・リピート率、月別CSV |
| 設定 | 組織情報編集・保存、実メンバーと権限の閲覧、共通の個人通知設定 |

## 追加・拡張API

- GET /organizers/{organizerId}/events/{eventId}: 下書き・非公開を含む詳細。主催者権限とイベント所属を確認。
- GET /organizers/{organizerId}/members: 実メンバー。membership行のない旧所有者も返す。
- GET /organizers/{organizerId}/analytics?from=YYYY-MM-DD&to=YYYY-MM-DD: 他主催者を混ぜず、日本時間の開催日で集計。
- 既存 GET /me/organizers を再利用し、websiteUrl/contactEmailを追加。ページング契約を維持。
- イベントの作成・更新では、下書きのカテゴリ・形式・日時・定員などを明示的にnullへ戻せる。説明は空文字可。公開・開催済みの必須条件、申込済みの定員制約は維持。

現行契約は [OpenAPI](../Backend/app/openapi/index.yaml)（61操作）を参照してください。

## 認証・安全性

参加者・主催者・管理者で同じHTTPクライアントとHttpOnly Cookieを使います。Next.jsの同一オリジンプロキシは、各画面で使うAPIを許可リストで中継します。更新はOriginを検証し、上流へ送るBearerはCookieからのみ生成します。認可は毎回Backendが行います。

主催者の選択IDだけをユーザー別sessionStorageに保持します。トークンは保存しません。主催者切り替え時は画面状態を破棄し、終了済みの取得結果を別主催者に表示しません。別タブのログイン・ログアウトとセッション失効時は私有データをクリアします。

イベント編集には取得時のversionをexpectedVersionとして送ります。競合は上書きせず入力を保持してエラー表示します。公開前の下書き作成に成功して公開だけ失敗した場合は、同じ下書きを再利用して再保存できます。通信自体が失敗して作成結果が不明な場合は、一覧で確認してから再操作してください。

CSVでは引用符・改行・カンマをエスケープし、数式として解釈される先頭文字を無効化します。各画面は読込・エラー・空状態・再取得に対応します。

## 集計と残る制約

- 分析は指定期間に開催するpublished/completedイベントが対象。申込が行われた日での集計ではありません。
- 参加率はchecked_in / 参加枠占有状態（pending/confirmed/checked_in/no_show）。取消率はcancelled / 全申込。
- リピート率は、期間内に2イベント以上でconfirmed/checked_inの人数 / 同状態のユニーク人数。比較期間に対する架空の増減やインサイトは表示しません。
- 削除APIはないため、履歴を保持する「開催中止」を使用。中止済みイベントの再公開はできません。
- メンバー招待・権限変更、パスワード変更、2段階認証、組織向け通知配信は未実装。現在の設定画面は個人の申込通知・リマインド・推薦通知と共通です。
- 一覧は全ページを読み、検索・ソート・CSVを画面側で実行します。大規模データではサーバー検索とページングUIへの移行が必要です。
- 当日受付の一覧は開催開始日の一致で抽出。複数日イベントの受付はイベント詳細の導線から開けます。
