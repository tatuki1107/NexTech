# API要件対応表

要件定義書5.2〜5.8とOpenAPI 1.3.0（54操作）に対するBackendの対応です。
Frontendの接続状況とは独立して記載しています。

| 要件 | API実装 | 検証 |
| --- | --- | --- |
| 5.2 検索・詳細 | キーワード、開催期間、カテゴリ、タグ、主催者ID・名前、開催形式、空席、ページング、参加条件 | 日本語部分一致・日付・タグ・空席・空ページ総数・URL公開権限 |
| 5.3 申込・キャンセル | イベント行ロック、重複防止、定員判定、キャンセル待ち・順位、先頭繰上げ、履歴と通知の原子性 | 並列8申込・同一ユーザー同時申込・キャンセル繰上げ・再申込・履歴 |
| 5.4 作成・編集 | 所属主催者の作成・編集・公開状態変更、参加条件、公開範囲、変更履歴 | 所属外403・必須値・不正更新ロールバック・主催者自身の公開 |
| 5.5 参加者・募集管理 | 参加者一覧・氏名／メール／申込ID検索、状態絞込み、募集集計、当日受付 | 申込ID検索・二重受付拒否・受付後の定員計上 |
| 5.6 マイページ | 申込一覧の分類、お気に入り主催者・カテゴリ登録解除と一覧、タグ・主催者による後継イベント | 本人データ分離・表示条件・後継イベント・保存データの閲覧権限再確認 |
| 5.7 サービス管理 | イベント・主催者・参加情報の一覧と詳細、期間・キーワード・状態検索、確認済み操作、公開停止・復帰、操作履歴 | 管理者権限・理由必須・主催者停止・管理者停止を主催者が解除できないこと・履歴 |
| 5.8 集計 | 月別開催数・申込数・参加数・受付数・申込率、カテゴリ／主催者ランキング、カテゴリ／主催者／形式別期間比較 | 東京日付境界、0件の月、集計軸・百分率・直前同日数の比較期間 |

認証はArgon2id、15分JWT、30日更新Cookie、更新ローテーション・再利用時の系列失効です。
認証済みリクエストはDBの最新ロール・ユーザー状態・論理削除を確認します。
共通エラーとリクエストIDを使用し、500エラーのログにも例外本文・SQL・機密値を含めません。

DBは19テーブル。0000〜0006の既存履歴を維持し、0007〜0008を追加適用します。
0007は既存の申込状態履歴にイベント・ユーザーIDを補完し、旧JSON履歴を補正します。
ER図とDrizzleスキーマはこの構成に同期しています。

集計仕様はBackend READMEのとおりです。取消イベントは開催実績集計に含めず、
管理者の公開停止は下書き状態と専用フラグで保持し、物理削除しません。

非機能要件のHTTPS終端・定期バックアップ・24時間運用はデプロイ先の運用設定です。
アクセス集中時の3秒要件は実運用相当環境での負荷試験が必要であり、
ローカル統合テストだけで達成保証するものではありません。
